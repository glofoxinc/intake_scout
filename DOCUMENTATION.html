START OF WORK, THEN REVIEW / QA

Intake Scout

You give the Jira key. Scout reads the whole ticket — comments, pictures, and files — then sets naming when you start the work, and posts the acceptance checks when you send it to Review or QA. Nothing is written until you say yes.

Works in Cursor Setup ~ 5 minutes, once Saves ~ 15 to 25 min per ticket

What you will see

After you type Intake Scout for AN-XXXX (your ticket), Scout returns one card.

On the cardIn simple words
Start of work Title (report or client first), one work label, Complexity size, and a clear description. AN: In Progress. PIC: often Build.
Review / QA Acceptance criteria for every ask on the ticket, a few basic test cases, and a tag on the assignee. Pictures and later comments are included.
A / B / C A writes this gate. B lets you edit first. C leaves Jira unchanged.

Who this is for

Insights / Glofox analysts on AN and PIC tickets. Same crew as Semantic Scout — run Intake Scout when the ticket starts and when it goes to QA. Run Semantic Scout before the pull request.

Before vs after

Without Intake Scout

You hunt a closed ticket to copy the title. The description stays as it was filed. At QA someone rereads comments and screenshots to write checks. That often waits.

With Intake Scout

One command. Start of work gets naming and a clean description. Review / QA gets a short list the assignee can tick, including what the pictures showed.

About 15 to 25 minutes back, each ticket

How it works

flowchart TD A["You: Intake Scout for AN-XXXX"] --> B["Read Jira + comments + files"] B --> C{"Status"} C -->|"In Progress or Build"| D["Title, label, size, description"] C -->|"Review or QA"| E["Acceptance criteria + a few test cases"] D --> F{"A / B / C"} E --> F F -->|"A"| G["Write this gate"] F -->|"C"| H["Jira unchanged"]

Setup — once, about 5 minutes

This is a Cursor skill, same idea as Semantic Scout.

  1. Open Cursor.
  2. In chat, type exactly
    Setup Intake Scout
  3. If it asks for Jira, answer once. Paginate should already be on for picture text.
  4. Prove it — type Intake Scout for AN-XXXX with your real ticket.
You are done when you see a card for start of work or for Review / QA, and Jira did not change until you picked A.

Daily use

Intake Scout for AN-XXXX

Use PIC-XXXX the same way. Scout uses the ticket’s current status.

After the card — reply with one letter

A
Write

Update only this gate. Then Scout reads the ticket back.

B
Edit first

You change a line, then write.

C
Leave

Nothing is written to Jira.

Example card

INTAKE SCOUT — START OF WORK Ticket: AN-XXXX Title: All Paginated Reports - Add column headers on every page Label: Report_Enhancement Size: S Description: Background + what to change + reports Reply A to write · B to edit · C to leave

If something fails

What you seeWhat to do
Skill not foundSay Setup Intake Scout. Restart Cursor once if it still does not appear.
No Jira textConnect Atlassian in Cursor, or paste the ticket key again.
Description did not changeStatus is not In Progress or Build yet, or the description was already clear.
No acceptance commentStatus is not Review or QA yet, or that comment is already there.
A check looks wrongPick B, or edit that one comment. Scout will not post a second Acceptance criteria list.
